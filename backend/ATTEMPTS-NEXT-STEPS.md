# NSCT practice persistence — proposed v3.3 step 10
This additive package assumes Steps 7–9 installed, including practice-core.mjs. It does not replace existing files, run a migration, publish a syllabus or grant admin access. Review with team before applying. Based on blueprint sections 7–9 and API contract BuildQuiz, Attempt, Answer and Result.

1. Extract into backend. From backend run `node --test src/attempts/practice-persistence.test.mjs` (5 tests). These use mock DB transactions, not PostgreSQL. Run `node prisma/add-attempts-v3.3.mjs` for dry-run. After team review run with `--apply`, then `npx.cmd prisma format` and `npx.cmd prisma validate`.
2. With Docker running, create a new migration: `npx.cmd prisma migrate dev --name add_attempt_persistence --create-only`. Confirm the new migration is unapplied and creates all six tables; append the contents of prisma/attempt-constraints.sql once to its migration.sql only. Do not change any of the previous five migrations or reset the DB. After review apply with `npx.cmd prisma migrate deploy`, `npx.cmd prisma generate`, `npx.cmd prisma migrate status`.
3. For local testing only, register AttemptsModule in src/app.module.js. Keep PrismaModule, AuthModule and ExamsModule and any existing controllers/providers. Add `import { AttemptsModule } from './attempts/attempts.module.js';` and add AttemptsModule to imports. If ExamsModule missing, add `import { ExamsModule } from './exams/exams.module.js';` and add it to imports as well. Confirm exams.guard.js exists. Start backend; use a real verified-user bearer token via approved authentication flow. No token bypass. Check Swagger and integration tests before enabling for clients.
4. POST /api/v1/attempts/custom with Idempotency-Key and BuildQuiz JSON. GET /attempts/{id}, PUT /attempts/{id}/answers/{itemId} with {"answer":"option ID"}, POST /attempts/{id}/submit, GET /attempts/{id}/result. Use actual UUIDs, and reviewed approved original bank and published active NSCT syllabus; no auto approval. Draft catalog or insufficient bank is expected to fail. No client score accepted. Test 401, 404 wrong owner, cross-edition topic 400, insufficient bank 409, duplicate request replay, changed request same key 409, invalid option, active result 409, repeated submit same score, answer save after submit 409, parallel save/submit, and no key disclosure before submit.

Limitations: Node pure-module tests and schema insertion smoke test pass; Prisma validation, PostgreSQL migration and Nest/Babel/Swagger integration not executed here. Only NSCT untimed practice with four options and 1/0/0 scoring; no history route, blueprint models, mock creation, deadline processing, integrity events or course routes yet. Practice service uses owner row lock; future mock operations must share lock order and account-wide result restrictions. Partial unique index reserves one active mock per user, but mock runtime is not implemented. Source rights and content approvals, full auth transport, DB-level immutable approved/snapshot enforcement, audit/rights revocation and integration testing are still required before production.
