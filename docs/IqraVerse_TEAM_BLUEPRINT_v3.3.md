## 3B. Secure Exam Mode (30%, reusable across all four exams)
- Secure mode mandatory for timed mock attempts; ordinary practice remains unrestricted. Proposed default policy: warn at first and second counted excursion, auto-finalize at third with reason `violation_limit` and flagged integrity status. Policy version and threshold fixed in attempt snapshot; admin configuration later via reviewed API. Before start, show rules, platform limits and accessible accommodations; no webcam, biometric, microphone, screen recording or OS lockdown in 30%.
- Web: request fullscreen via user action where supported, listen to visibility/fullscreen events, restrict clipboard actions within exam UI (not global). Mobile: detect app background, apply screenshot protection where supported (not guaranteed on iOS); no managed-device lockdown assumed. Unsupported controls are disclosed; use reasonable accessibility/OS interruption handling. Ordinary browsers/apps cannot prevent all screen changes or second-device use. Never claim cheating-proof.
- Count one excursion, not multiple correlated events: client sends one `screen_away` report with unique eventId per episode, after a proposed 3-second grace period (coalesce tab hidden/fullscreen exit/background; re-arm only after return). Report other signals as advisory if added later; clipboard/screenshot/network loss alone do not trigger termination. Accessibility accommodations use reviewed policy versions, not hidden bypasses. Client telemetry is untrusted and can be suppressed; counted events are policy signals, not proof of cheating.
- Backend owns time, score, violation count, finalization and status; secure mock starts atomically with one active secure attempt per user across variants; bind to authenticated session family (stable across token refresh), reject other session access to active attempt; second independently logged-in device cannot start another mock or take over. Same session replay or duplicate browser tabs cannot be fully prevented by this design. Resume after reconnect on bound session; no clock pause; server expiry wins. Support documented audited recovery for lost session before release. Never count disconnect as cheating. Reject unauthorized/expired events, deduplicate by attempt/event UUID, serialize events/save/finalize; third counted event finalizes saved answers exactly once. No keys until finalized; server blocks AI (when implemented) and other answer-revealing learning endpoints for same account during active secure mock, independent of UI hiding. Minimize logs, restrict admin access, document retention and review process; no automatic misconduct accusation.
- UI: display warning count, secure status, timer, saved state, flagged completion reason and capability limitations. Web/mobile use shared API fields, not client-calculated penalties. Verify no keys before finalization, server-time expiry, repeat event idempotency, overlapping events, reconnect, other-session denial, ordinary practice unaffected, and no cross-exam/role leakage. Fullscreen, app-switch detection and screen protections tested on actual supported platforms. A bypassable client cannot establish official proctoring; this is exam-integrity support for practice mocks.

## 4. Student and teacher workflows
Student signs up once → chooses NSCT, MDCAT, NAT or IELTS workspace → study or Build My Quiz (topic/subject/difficulty/count) or Exam Simulation (published blueprint; full NSCT/MDCAT, labeled starter NAT/IELTS) → answer → submit/expire → review → targeted practice. No course enrollment required for independent preparation. Backend fixes attempt order, item versions and deadlines; saves answers; finalizes once; never sends keys before finalization.
Teacher applies with evidence → admin verifies → creates course/product draft → adds recorded content/notes and reviewed assessments → submits → admin approves/publishes revision → student discovers and enrolls for free → learns and completes lessons → teacher sees course-specific progress. Paid purchasing is a later sandbox workflow. Proposed course completion = completed required lessons / required lessons in enrolled published revision; zero required lessons = not applicable. Quiz accuracy tracked separately. Preserve course revision access and progress; define migration of old enrollments before course release. Admin can revoke access immediately without erasing historical attempts; instructor cannot self-approve or view private independent data.

## 5. Assessment and analytics
30% score: sum approved correct-answer marks; MDCAT full mock max 180; other assessments use their own blueprint maximum. IELTS starter reading scores are raw objective marks only, not bands. Practice accuracy = correct answered / answered, with denominator visible; no answered items = unassessed. For weak topics, retain v2 proposed rule: below 60% on at least 3 distinct answered logical questions within the same user/exam variant/syllabus/topic and mode scope; latest eligible graded answer per logical question (prevents edited versions/retries inflating evidence). Exactly 60% not weak; fewer than 3 = insufficient. Unanswered counts zero in the current proposed/confirmed mock scoring policies but not in mastery accuracy. Separate practice/mock/course filters; default independent analytics must not include course results. No cross-exam aggregate. Recommendations link to eligible reviewed content; explain trigger. Weighted formula at 60% needs explicit review and golden tests.

## 7. Unified logical database baseline (not executable migrations)
UUID PKs, UTC timestamps, snake_case DB, camelCase JSON; FK/unique constraints and indexes on scope/status/ownership. Names below are proposed canonical names; review against actual branch schemas before migration. Do not create duplicate old/new tables for the same entity.
- Identity: users, profiles, roles, user_roles (grant/revoke metadata), role_permissions, auth_identities (later providers), refresh_sessions, verification_tokens, reset_tokens, instructor_verifications (evidence/review). No tutor tables or role.
- Curriculum: exams → exam_variants → syllabus_versions (edition, applicability_year, source_uri, status) → subjects → chapters → topics → curriculum_lessons. One published edition per variant for new attempts; historical references preserved. Variant and syllabus filters must agree.
- Content: sources (rights/provenance/reviewer), assets (owner, private storage key, hash, MIME, size), resources, resource_versions (immutable content and independent review/index status), passages. Link approved curriculum lessons to resources; keep instructor ownership and scope. Preserve optional past-paper identity/year/edition and question order through source metadata or a paper-to-question mapping; do not store an entire paper as one scored item.
- Questions: questions (logical ID, topic, owner, platform/course scope), question_versions (format, difficulty, prompt, passage, options_json, answer_key_json, explanation, source_version, status, marks), moderation_reviews. For NSCT and MDCAT enforce exactly one valid correct option among four options as the proposed default, approved immutable version, source and explanation. Initial NAT and IELTS reading objective items use the same single_select format, with optional reading passage and exactly one approved key. Future mixed formats use validated per-format JSON; not active now. One current approved version per logical question, snapshot old versions.
- Assessments: blueprints (variant, syllabus, version, duration, scoring policy, retake limit, full-length flag, status), blueprint_sections (subject quotas, allowed formats), difficulty quotas at paper level; assessments (practice/mock/course), assessment_items; attempts (user, assessment, variant, syllabus, mode, status, start/deadline/submission, marks), attempt_items (question version, order, presentation snapshot, marks), attempt_answers (one per item, answer, grading, timestamp), idempotency_records. Unique item order/logical question per attempt; locks/transactions for save/finalize, immutable keys, expiry job + lazy checks.
- Import and exam integrity additions (proposed migration design): import_batches and restricted staging records with source checksum, source reference, parser outcome and review status; attempt_integrity_events (attempt ID + unique event UUID, type, server timestamp, session family reference), attempt policy snapshot, counted violations, completion reason and integrity flag. Unique active secure attempt per user; lock on finalization. Do not persist unnecessary device identifiers or raw clipboard contents.
- Courses: categories, courses (instructor, variant, category, product_type, state), course_revisions, course_lessons, course_revision_lessons (published membership), course_assessments, enrollments (user/course, revision, access state), lesson_progress (enrollment + revision lesson, completed_at). Keep curriculum and course lesson namespaces distinct; support notes/test packages without duplicating exam catalog. Access and progress tied to approved revision; no live payment fields required for 30%.
- Analytics: compute from eligible finalized answers with indexes; no duplicate counters initially. Later versioned topic_metrics/recommendation rules if necessary. audit_events record privileged actions. Later: private_documents, rag_chunks_manifest, ai_runs, ai_citations, separate provisional AI practice storage, marketplace_listings, mock_transactions, notifications. RAG permission checks before and after retrieval; shared/private isolation and revoke-before-purge. No tutoring schema.
